## 2. Data Collection Simulation

### 2.1 Choice of reference data

The dataset is **simulated**. It is generated with a fixed random seed (42), so every run is reproducible.

Reasons for simulation:
- The environment used to build this work could not download public datasets, so the characteristics of a real file could not be verified.
- A simulated dataset with known injected errors lets us check whether each cleaning step finds and fixes the problem it targets. With real data, a missed error cannot be distinguished from an error that was never present.

**Recommended for submission:** repeat this pipeline on a real public dataset, such as the Kaggle "DataCo Smart Supply Chain" dataset, or on shipment data from the internship organization if it is shared. Check the license first. The steps in Section 4 apply unchanged. Column names and thresholds may need adjustment.

### 2.2 Dataset characteristics

One year (2024) of shipment records across three warehouses in one metropolitan region. The raw file has 5,060 rows and 11 columns, including 60 deliberately duplicated records.

| Field | Type | Description |
|---|---|---|
| shipment_id | Text | Unique shipment identifier |
| carrier | Text | Transport partner (five carriers) |
| warehouse | Text | Origin warehouse (three sites) |
| mode | Text | Road, Rail, or Air |
| dispatch_time | Timestamp | When the shipment left the warehouse |
| delivery_time | Timestamp | When the shipment was delivered |
| distance_km | Number | Route distance in kilometres |
| weight_kg | Number | Shipment weight in kilograms |
| freight_cost_inr | Number | Freight cost in Indian rupees |
| status | Text | Delivered, In Transit, Delayed, or Returned |
| destination_pin | Number | Destination postal code (stored as a number) |

Distance, weight, and cost are right-skewed, which is typical of shipment data: most parcels are light and short-haul, with a long tail of heavy or long-distance shipments.

## 4. Methodology: Cleaning and Preprocessing Steps

The pipeline runs in a fixed order. Each step is logged with row count and missing-cell count.

### 4.1 Removing duplicates
- **What:** Remove exact duplicates first. Then remove duplicates on `shipment_id` after timestamps are parsed.
- **Why two passes:** the first catches identical copies. The second catches copies whose formatting differs.
- **Why shipment_id:** it is the business key for transactional data.
- **Effect:** 56 exact and 4 ID-level duplicates removed, leaving 5,000 unique shipments.

### 4.2 Standardizing text labels
- **What:** trim whitespace, convert carrier names to a single case, unify warehouse separators to underscores.
- **Why:** group-by operations treat `BLUEDART_SIM` and `BlueDart_Sim` as different groups.
- **Effect:** each carrier and warehouse collapses to one canonical label.

### 4.3 Parsing timestamps
- **What:** parse each timestamp against known formats. Unparseable values become missing.
- **Why:** explicit format strings are safer than letting the parser guess, because a guess can swap day and month.
- **Effect:** all dispatch times parsed correctly. Nothing was discarded.

### 4.4 Logical validity checks
- **What:** (a) if delivery is earlier than dispatch, set delivery time to missing; (b) convert negative distances to positive.
- **Why:** these rules encode physical facts the data must obey.
- **Judgment call:** rule (b) assumes a sign-entry error, which is the most likely cause. This must be confirmed against the source system. Setting these values to missing would be the more cautious choice.
- **Effect:** 20 timestamps and 14 distances corrected.

### 4.5 Outlier detection
- **What:** interquartile range (IQR) rule, first described by Tukey (1977). Values more than k × IQR beyond the quartiles are flagged. Applied on a log scale because weight and cost are right-skewed.
- **Why this method:** it assumes no normal distribution and is easy to explain.
- **Handling:** flagged values are set to missing and imputed, not deleted, so no records are lost.
- **Threshold choice:** tested k = 1.5, 2, 3 (Section 6.3). Final settings: **k = 3 for weight and distance, k = 2 for cost**. At k = 3, cost errors survived cleaning.
- **Effect:** 38 weight values and 16 cost values flagged. All remaining weights are below 100 kg.

### 4.6 Handling missing values
- **What:** numeric fields are filled with the median within each transport mode. Categorical fields (carrier, status) are filled with an explicit `"Unknown"` category.
- **Why median:** not moved by extreme values, which matters for skewed data.
- **Why group by mode:** Air freight costs far more than Road. A single overall median would understate Air and overstate Road.
- **Why "Unknown":** filling with the most common carrier invents a fact and biases carrier comparisons toward the largest carrier.
- **Delivery time:** rebuilt from dispatch time plus imputed transit time, keeping timestamps and durations consistent.

### 4.7 Normalization
- **What:** cost and weight get `log1p` transform, then z-score. Distance gets min-max scaling to 0–1.
- **Why:** log transform reduces the long tail's influence. Z-scores put variables on a common scale. Min-max keeps distance bounded.
- **Choice of scaler:** standard scaler rather than robust scaler, because outliers were already removed.

### 4.8 Final validation
Assertions stop the run if: IDs are not unique, a required field is missing, distance or transit time is negative, or transit time is inconsistent with timestamps.

### 5.1 generate_data.py

```python
"""
Simulate a raw shipment-records dataset for a regional logistics operator.
All records are SYNTHETIC. Quality problems are injected deliberately so the
cleaning pipeline has realistic issues to detect and fix.
"""
import numpy as np
import pandas as pd

rng = np.random.default_rng(42)
N = 5000
carriers = ["BlueDart_Sim", "Delhivery_Sim", "EcomExpress_Sim", "Ekart_Sim", "XpressLite_Sim"]
warehouses = ["WH_BLR_01", "WH_BLR_02", "WH_MYS_01"]
modes = ["Road", "Rail", "Air"]
statuses = ["Delivered", "In Transit", "Delayed", "Returned"]

start = pd.Timestamp("2024-01-01")
dispatch_days = rng.integers(0, 365, N)
dispatch = start + pd.to_timedelta(dispatch_days, unit="D") + pd.to_timedelta(rng.integers(0, 86400, N), unit="s")

mode = rng.choice(modes, N, p=[0.6, 0.25, 0.15])
distance_km = np.where(mode == "Air", rng.uniform(150, 900, N),
              np.where(mode == "Rail", rng.uniform(100, 700, N),
                       rng.uniform(5, 250, N)))
speed = np.where(mode == "Air", 500, np.where(mode == "Rail", 60, 40))
transit_hours = distance_km / speed + rng.gamma(2.0, 2.0, N)
delivery = dispatch + pd.to_timedelta(transit_hours, unit="h")

weight_kg = np.round(rng.lognormal(0.5, 0.8, N), 2)
freight_cost = np.round(40 + 1.8 * distance_km * (1 + 0.4 * (mode == "Air")) + 6 * weight_kg + rng.normal(0, 25, N), 2)
# shipping cost is the same for every mode bucket here; keep positive
freight_cost = np.clip(freight_cost, 30, None)

df = pd.DataFrame({
    "shipment_id": [f"SH{100000 + i}" for i in range(N)],
    "carrier": rng.choice(carriers, N),
    "warehouse": rng.choice(warehouses, N, p=[0.45, 0.35, 0.20]),
    "mode": mode,
    "dispatch_time": dispatch,
    "delivery_time": delivery,
    "distance_km": np.round(distance_km, 1),
    "weight_kg": weight_kg,
    "freight_cost_inr": freight_cost,
    "status": rng.choice(statuses, N, p=[0.82, 0.05, 0.10, 0.03]),
    "destination_pin": rng.integers(560001, 560100, N).astype(float),
})

# ---- inject realistic data-quality problems ----
def inject_missing(col, frac):
    idx = rng.choice(N, int(N * frac), replace=False)
    df.loc[idx, col] = np.nan

inject_missing("weight_kg", 0.06)
inject_missing("distance_km", 0.04)
inject_missing("freight_cost_inr", 0.05)
inject_missing("delivery_time", 0.03)
inject_missing("carrier", 0.02)

# Outliers: extreme weights (data entry errors), huge costs
o = rng.choice(N, 40, replace=False)
df.loc[o, "weight_kg"] = df.loc[o, "weight_kg"] * 1000   # grams entered as kg
o2 = rng.choice(N, 25, replace=False)
df.loc[o2, "freight_cost_inr"] = df.loc[o2, "freight_cost_inr"] * 25  # extra zero

# Negative / impossible values
neg = rng.choice(N, 15, replace=False)
df.loc[neg, "distance_km"] = -df.loc[neg, "distance_km"].abs()

# Inconsistent categorical labels
case_idx = rng.choice(N, 300, replace=False)
df.loc[case_idx, "carrier"] = df.loc[case_idx, "carrier"].str.upper()
ws_idx = rng.choice(N, 150, replace=False)
df.loc[ws_idx, "warehouse"] = df.loc[ws_idx, "warehouse"].str.replace("_", " ")
df.loc[ws_idx[:50], "warehouse"] = "  " + df.loc[ws_idx[:50], "warehouse"] + " "

# Delivery before dispatch (timestamp error)
bad_ts = rng.choice(N, 20, replace=False)
df.loc[bad_ts, "delivery_time"] = df.loc[bad_ts, "dispatch_time"] - pd.Timedelta(hours=3)

# Exact duplicate rows (double-posted records)
dups = df.sample(60, random_state=1)
df = pd.concat([df, dups], ignore_index=True)

# Mixed date formats in a text column stored as string
df["dispatch_time"] = df["dispatch_time"].dt.strftime("%Y-%m-%d %H:%M:%S")
fmt_idx = rng.choice(len(df), 200, replace=False)
df.loc[fmt_idx, "dispatch_time"] = pd.to_datetime(df.loc[fmt_idx, "dispatch_time"]).dt.strftime("%d/%m/%Y %H:%M")
df["delivery_time"] = pd.to_datetime(df["delivery_time"]).dt.strftime("%Y-%m-%d %H:%M:%S")

df.to_csv("raw_shipments.csv", index=False)
print("raw rows:", len(df))
print(df.isna().sum())
```

### 5.2 clean_pipeline.py

```python
import json
import numpy as np
import pandas as pd

log = []  # record what each step did, for the report
def record(step, df, note=""):
    log.append({"step": step, "rows": len(df), "missing_cells": int(df.isna().sum().sum()), "note": note})

raw = pd.read_csv("raw_shipments.csv")
record("0. Raw load", raw)
df = raw.copy()

# 1. Remove exact duplicates
n_before = len(df)
df = df.drop_duplicates()
record("1. Remove exact duplicates", df, f"removed {n_before - len(df)} rows")

# 2. Standardise text fields: trim whitespace, unify case and separators
for col in ["carrier", "warehouse", "mode", "status"]:
    df[col] = df[col].astype("string").str.strip()
df["carrier"] = df["carrier"].str.title()
df["warehouse"] = df["warehouse"].str.replace(" ", "_").str.upper()
record("2. Standardise text labels", df, "trim, case, separator unification")

# 3. Parse timestamps with mixed formats
def parse_ts(s):
    s = str(s)
    try:
        return pd.to_datetime(s, format="%Y-%m-%d %H:%M:%S")
    except (ValueError, TypeError):
        return pd.to_datetime(s, format="%d/%m/%Y %H:%M", errors="coerce")
df["dispatch_time"] = df["dispatch_time"].map(parse_ts)
df["delivery_time"] = df["delivery_time"].map(parse_ts)
record("3. Parse mixed timestamp formats", df, f"unparseable dispatch: {df['dispatch_time'].isna().sum()}")

# 3b. Duplicates that differ only in formatting: dedupe on business key
n_before = len(df)
df = df.drop_duplicates(subset=["shipment_id"], keep="first")
record("3b. Deduplicate on shipment_id", df, f"removed {n_before - len(df)} ID-level duplicates")

# 4. Logical validity rules
invalid_ts = df["delivery_time"] < df["dispatch_time"]
neg_dist = df["distance_km"] < 0
print("invalid timestamp order:", int(invalid_ts.sum()), "| negative distance:", int(neg_dist.sum()))
df.loc[invalid_ts, "delivery_time"] = pd.NaT   # cannot be trusted, treat as missing
df.loc[neg_dist, "distance_km"] = df.loc[neg_dist, "distance_km"].abs()  # sign error
record("4. Logical checks", df, f"timestamp order fixed/NaN: {int(invalid_ts.sum())}, negative distance sign-fixed: {int(neg_dist.sum())}")

# 5. Derive transit time (hours) before imputation, from valid timestamps
df["transit_hours"] = (df["delivery_time"] - df["dispatch_time"]).dt.total_seconds() / 3600

# 6. Outlier detection with IQR on log scale (costs and weights are right-skewed)
def iqr_bounds(s, k=3.0):
    q1, q3 = s.quantile([0.25, 0.75])
    iqr = q3 - q1
    return q1 - k * iqr, q3 + k * iqr

outlier_report = {}
K_BY_COL = {"weight_kg": 3.0, "freight_cost_inr": 2.0, "distance_km": 3.0}  # k tuned by sensitivity check
for col in ["weight_kg", "freight_cost_inr", "distance_km"]:
    s = df[col].dropna()
    s_log = np.log1p(s.clip(lower=0))
    lo, hi = iqr_bounds(s_log, k=K_BY_COL[col])
    mask = (np.log1p(df[col].clip(lower=0)) > hi) | (np.log1p(df[col].clip(lower=0)) < lo)
    outlier_report[col] = {"flagged": int(mask.sum()),
                           "median": float(s.median()),
                           "max_before": float(s.max())}
    df.loc[mask, col] = np.nan   # set aside; imputed in step 7
print(json.dumps(outlier_report, indent=2))
record("5. Outlier detection (IQR, log scale, k=3 weight/distance, k=2 cost)", df, "outliers set to NaN for imputation")

# 7. Missing value handling
miss_before = df.isna().sum().to_dict()
# Numeric: median imputation within the mode group (air costs differ from road)
num_cols = ["weight_kg", "distance_km", "freight_cost_inr", "transit_hours"]
for col in num_cols:
    df[col] = df.groupby("mode")[col].transform(lambda s: s.fillna(s.median()))
# Categorical: explicit 'Unknown' category keeps the row, avoids inventing a carrier
df["carrier"] = df["carrier"].fillna("Unknown")
df["status"] = df["status"].fillna("Unknown")
record("6. Impute missing values", df, "numeric: group median by mode; categorical: 'Unknown'")

# 8. Re-derive transit after imputation so it is consistent with timestamps
df["delivery_time"] = df["delivery_time"].fillna(df["dispatch_time"] + pd.to_timedelta(df["transit_hours"], unit="h"))

# 9. Normalisation
# Log transform for skewed cost, then z-score for model input; min-max for distance
df["log_freight_cost"] = np.log1p(df["freight_cost_inr"])
df["log_weight"] = np.log1p(df["weight_kg"])
for col in ["log_freight_cost", "log_weight", "transit_hours"]:
    df[col + "_z"] = (df[col] - df[col].mean()) / df[col].std()
df["distance_minmax"] = (df["distance_km"] - df["distance_km"].min()) / (df["distance_km"].max() - df["distance_km"].min())
record("7. Normalisation", df, "log1p + z-score; min-max for distance")

# 10. Final validation checks
assert df["shipment_id"].is_unique, "duplicate IDs remain"
assert df.isna().sum()[["weight_kg", "distance_km", "freight_cost_inr", "transit_hours"]].sum() == 0
assert (df["distance_km"] >= 0).all()
assert (df["transit_hours"] >= 0).all()

df.to_csv("clean_shipments.csv", index=False)
pd.DataFrame(log).to_csv("pipeline_log.csv", index=False)
print(pd.DataFrame(log).to_string(index=False))
print("missing before imputation:", miss_before)
print("final shape:", df.shape)
print("final missing:", int(df.isna().sum().sum()))
```

## 7. Limitations

- **Simulated data.** Results describe the pipeline's behavior on generated data. Real data will contain error types not represented here.
- **Residual cost errors.** Five cleaned records still exceed ₹5,000 (maximum ₹7,150) against a median near ₹400. These are probably errors, but this has not been confirmed against ground truth. On real data they need manual review before any cost model.
- **Sign-correction assumption.** Negative distances were made positive. Probable, but unverified.
- **Imputation uncertainty.** Median imputation understates variability. Keep imputation flags as features in modeling, or evaluate with this in mind.
- **Threshold dependence.** Thresholds were chosen by inspection on this dataset and should be tested on another before being treated as general.
- **No external validation.** Not compared with carrier invoices or GPS logs.

## 8. Reflection: Data Quality and Decision-Making in Logistics

- **Averages mislead without cleaning.** The raw mean weight is nearly nine times the cleaned mean. A planner reading the raw average might overestimate vehicle requirements and book more capacity than needed. Median reporting and outlier review are decision-relevant.
- **Duplicates and labels distort operational counts.** If one carrier appears under two spellings, a carrier-performance review shows two smaller carriers instead of one large one, and may recommend the wrong contract changes.
- **Checks are only as trustworthy as their parsing.** The timestamp error in Section 3 would have produced a wrong delivery-reliability figure. Validate every quality metric by a second method before it informs a decision.
- **Cleaning choices propagate.** Median versus mean, "Unknown" versus a guessed value, and deleting versus imputing all affect every model and KPI built afterward. Documenting and logging those choices is what allows a manager to trust the analysis and a colleague to reproduce it.
